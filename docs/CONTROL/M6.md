## Протокол фазы (время — UTC; `date -u`)

- 2026-09-28 — ветка `stage/mtpe-M6` с `main` (после merge M5 `dc840da`). D133–D136
  (ядро M6) + D137–D139 (UI) — в `docs/DECISIONS.md`.
- **Развилка** (D133): `Pipeline.run_translating` — единственная точка от воркера;
  `mt_pe` → `_run_mt_pe(repo, job, control_check)`; `single` — прежний движок. Фазы
  `m_draft → m_postedit → m_assemble` с `repo.set_phase` на границах + `repo.set_phase
  (None)` после. Прогресс §4.4: `_progress(done, total, is_final)` = `done/(2·total)`
  (m_draft) / `(total+done)/(2·total)` (m_postedit); в конце `1.0`. L2-бандл
  (глоссарий+стиль) — только если `glossary.enabled` (иначе `glossary: absent`);
  `analysis`-прогрев — только если глоссарий не собран.
- **Прогрев** (D134): единый `app/llm/warmup.py::warmup_profile(settings, profile)` —
  «свой клиент» воркера; chat → `POST /chat/completions` (ping, `max_tokens:1`,
  `extra_body`), completions → `POST /completions` (шаблон `mt_draft` с ping,
  `max_tokens:1`); `response.model ≠ profile.model` → `model_mismatch`, таймаут →
  `warmup_timeout`. Мт/постредактура — прогрев внутри `DraftPhase`/`PostEditPhase`
  (M3/M4); `analysis` — в `_run_mt_pe` перед бандлом, `translation`/`fill` — в single.
- **Остановка** (M6-6/M6-7): 6 причин несут `details={profile, segment_ids}`;
  `_format_stop_reason` → `<code>; профиль <p>; сегментов <N>: <ids>`; `settings_invalid`
  — на старте `_execute` (проверка снапшота конфига перед пайплайном).
- **API/UI** (D136, D137–D139): `job_facts` + `GET /api/jobs/{id}/postedit` (D136);
  5-я строка мастера, строка задания `· MT+PE`+фаза, секция «Потредактура» + страница
  `/jobs/{id}/postedit` (server-render, no-JS, 3 строки/сегмент, diff на сервере,
  пагинация `ui.page_size`, фильтр по флагу-ссылками).
- Тесты: `tests/test_mtpe_m6.py` (7 функций / 7 кейсов). Полный прогон mt_pe
  (`complex.epub`, en→ru) — фазы + прогресс + прогрев (M6-2/M6-3/M6-10). Остальные —
  изолированные (чистые функции / один LLM-вызов / данные представления), без полного
  тракта. M6-1/M6-5/M6-10(API) — инспекция + регрессия (no regression в существующих
  web/worker-тестах).
- Регрессия: ruff 0 / mypy 0 (95) / **pytest 501** (база 494 + 7, ни один прежний
  не удалён) — полный прогон 1433 с: **500 passed + 1 load-flake**.
- Load-flake (НЕ регрессия M6): `test_e3_worker.py::test_e3_4_double_worker_single_execution`
  упал в полном параллельном прогоне на `w1.wait(timeout=180)` (субпроцесс воркера не
  уложился в 180 с под нагрузкой ~500 тестов). В изоляции проходит за **5.36 с**
  (4-й раз за сессию). Режим отказа — таймаут ожидания субпроцесса, не ассерция по
  поведению M6; прогрев M6 добавляет пренебрежимо мало (пинг mock). Предсуществующая
  нестабильность под нагрузкой, не связана с M6.
