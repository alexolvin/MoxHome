## 3. Корневая причина
`BookStore` (L2.8) был корнем `books/<book_key>/<source_hash>/` — в той же `books/`,
где лежат исходные книги. `book_key` = basename файла источника (`book_key_of`).
При книге в библиотеке (`books/v1_en.epub` — файл) `path.parent` = `books/v1_en.epub`
= **файл**, и `Path.mkdir(parents=True, exist_ok=True)` бросает `FileExistsError`:
`exist_ok` гасит только случай «путь существует как каталог», а не «как файл».

Почему приёмка V1 (13/13 PASS) дефект не поймала:
- все харнесы V1.5–V1.13 использовали изолированные временные storage-root
  (`_make_u1_storage`), где `books/` было пустым;
- модульные тесты S/L-стадий ставят книги в `books/`, но при
  `glossary.enabled: false` — путь store не исполнялся;
- фиксер `tests/fixtures/epub/complex.epub` всегда передавался путём из
  `tests/fixtures/` (вне `books/`), где basename `complex.epub` не совпадал
  ни с одним файлом библиотеки — каталог store `books/complex.epub/` создавался
  легально (см. п.6).
Т.е. дефект лежал именно на пересечении «книга лежит в `books/`» + «глоссарий
включён» — условие, которое в тестовых средах никогда не совпадало.

## 4. Фикс (одна точка)
`app/glossary/store.py`:
```python
class BookStore:
    #: Зарезервированное поддерево store внутри `books/` (D81): имя не может
    #: быть именем книги-файла без риска столкновения с данными store.
    _STORE_SUBDIR = "_book_store"

    def __init__(self, root: Path) -> None:
        self._root = root / self._STORE_SUBDIR
```
- Новый layout: `books/_book_store/<book_key>/<source_hash>/` (docstring модуля
  обновлён с обоснованием).
- Все 7 вызовов идут через API `BookStore` (pipeline.py ×5, service.py ×1, тесты),
  фикс в одной точке — других мест в коде путь не строится.
- Имя `_book_store` зарезервировано: точка/подчёркик в начале исключают
  столкновение с типичными именами книг; даже при гипотетическом файле
  `books/_book_store` `mkdir(exist_ok=True)` продолжит падать — это корректно
  (символическая резервация, документирована в docstring).

## 7. Урок (для следующих фаз)
Дефекты, лежащие на пересечении «данные пользователя в стандартной позиции» +
«опциональная фича включена», не поймаются тестами, если фича в тестах
выключена либо данные всегда в изолированных путях. При вводе реальных
окружений (реальный LLM, реальные книги в `books/`) первые прогоны обязаны
идти по «сквозному» сценарию (книга из библиотеки + включённые опции), а не
по фиксерам.
