## 2. Модель — thinking: измерено поведение

### БЕЗ `enable_thinking` (max_tokens 60) — reasoning попадает в контент:
```
finish_reason: length
content: 'We need answer user\'s request: translate into German: "The quick brown fox
jumps over the lazy dog." User says "Ответ — только перевод." Means response only
translation. Need final only German transla...'
```
Ответ обрезан по `max_tokens`, контент засорён рассуждением — структурированный
вывод движка (XML) и анализа (JSON) не парсится. Прогон невозможен.

### С `chat_template_kwargs: {enable_thinking: false}` — чистый ответ:
```
finish_reason: stop
content: 'Der schnelle braune Fuchs springt über den faulen Hund.'
system_fingerprint: vllm-0.26.0-tp2-6ee7486e
```

## 3. Механизм D80

Добавлено поле `LLMProfile.extra_body: dict[str, Any]` (дефолт `{}`) —
passthrough в оба разрешённых LLM-клиента:
- движковый `LLM` (`app/adapters/epub_engine/engine.py`, `extra_body=` kwarg) —
  translation/fill;
- `AnalysisClient` (`app/llm/analysis.py`, `request_body.update(profile.extra_body)`).

Задокументировано в `config/config.example.yaml` (`extra_body: {}` в 3 профилях +
комментарий про Qwen3/vLLM). Конфиг: `extra_body: {chat_template_kwargs:
{enable_thinking: false}}` во всех 3 профилях.

## 5. Ложный прогон на реальном LLM до D80 (фиксация проблемы)

До D80 первый реальный прогон был невозможен: thinking-модель засоряла ответ
рассуждением. После D80 все прогоны V1R идут с `enable_thinking: false` и
дают парсируемый структурированный вывод.
