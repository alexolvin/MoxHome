## Протокол фазы (время — UTC; `date -u`)

- 2026-09-28 — ветка `stage/mtpe-M4` с `main` (после merge M3 `8bab026`).
- **Транспорт** (`app/llm/postedit.py`, §4.9): третья ветвь того же клиента `app/llm/`
  (второго клиента нет): `POST {base_url}/chat/completions` (профиль `postedit`, `api: chat`);
  ответ JSON-объект `{"text": …, "edits": [{type, note}]}`. Прогрев §4.6 — `max_tokens: 1`,
  `warmup_timeout_s`. Повторы — только транспортные (таймаут, 5xx, обрыв); 4xx/не-JSON —
  стоп. Токены — в учёт `profile=postedit` (`_UsageAccumulator`), сырой запрос/ответ — в
  `raw/pe_<label>_attempt_<n>.json`. Схема ответа (H1–H7) — в промпте, `response_format`
  не используется.
- **Проверки** (`app/mtpe/checks.py`, §4.5): жёсткие H1–H7 (любая → следующий шаг
  лестницы): H1 — JSON валиден + каждый `edit.type` в таксономии; H2 — мультивыно
  маркеров `text` == мультивыно `src_encoded` + вложенность (порядок может отличаться);
  H3 — язык `text` без маркеров == целевой (сегменты ≥ `lang_check_min_words`, прямой
  сравнитель, seed 0); H4 — `text` не пуст и ≠ `src_plain`; H5 —
  `|sent(text) − sent(src)| ≤ max_sentence_delta`; H6 — `edits` пуст ⇒ `text` без маркеров
  == черновик (в белом пространстве); H7 — у сегментов с `\n` число строк `text` ==
  исходнику. Мягкие S1–S3 (флаги, не блокируют): S1 — верифицированный термин глоссария,
  найденный в исходнике, в `text` в форме парадигмы, иначе `glossary_miss`; S2 —
  нормированное расстояние Левенштейна `text`/черновик ≤ `max_edit_ratio`, иначе
  `heavy_edit`; S3 — мультивино цифровых последовательностей `src` == `text`, иначе
  `numbers_mismatch`.
- **Лестница** (`app/mtpe/postedit.py`, §4.6): попытка 1 (обычная); попытка 2 (та же +
  список нарушенных жёстких проверок); попытка 3 (по предложениям регуляркой
  `(?<=[.!?…])\s+`, пропуск, если пара маркеров пересекает границу предложения —
  `_markers_balanced`). Пропуска попыток 1–3 **собираются** в склейку попытки 3 (правки
  не выбрасываются — иначе H1/H6 обходятся; D129). Все провалены → `pe_rejected`: итог =
  черновик (флаг `markup_dropped`, только без структурных) либо остановка
  `pe_unrecoverable` (структурные элементы / `draft_bad`).
- **Контекст** (§4.2/§4.1): предыдущие `mtpe.context_segments` сегментов той же главы
  (цепочка = `spine_idx`), формат `[{id}]\nOriginal: {src_encoded}\nFinal: {итог}`. Итоги
  прошлых сегментов берутся из `finals`, **обновляемого по мере прогона** (иначе контекст
  следующего сегмента пуст — D130).
- **6 блоков входа модели** (§4.2): (1) имена языков (`mt_name`); (2) стиль-профиль;
  (3) термины глоссария, найденные в сегменте (`contains_form`; `absent` — если глоссария
  нет → `pe_report` `glossary: absent`); (4) контекст; (5) `src_encoded`; (6) черновик.
  `draft_bad` → строка непригодности (§4.3, из промпта, тип правки ACC-RETRANSLATE), модель
  переводит с оригинала, S2 пропускается.
- **Системные остановки** (§4.6): после каждой `check_every_segments` обработанных:
  `pe_rejected`-доля > `max_rejected_ratio` → `pe_reject_ratio_exceeded`; `heavy_edit`-доля
  > `max_heavy_edit_ratio` → `pe_overedit` (оба — `PostEditStopError`, M6 → FAILED).
- **Аудит** (§4.7): `quality.log` (100 % сегментов с правками/флагами) + `pe_report.json`
  (распределение типов правок, попытки, `pe_rejected`/`heavy_edit`/`markup_dropped`/
  `numbers_mismatch`, медиана/p95 ratio, `glossary` present/absent).
- **Схема/репо:** `tokens_postedit` (колонка + миграция + инвариант E4-5
  `total = перевод+fill+analysis+mt+postedit`), `add_profile_tokens` принимает `postedit`.
  Фаза не создаёт строку `jobs`: `add_tokens` без задачи — no-op, `add_profile_tokens` —
  в `job_tokens` (без FK) — `job_id` = строка.
- Тесты: `tests/test_mtpe_m4.py` (10 функций / 13 кейсов: M4-1…M4-10, M4-7 ×2, M4-8 ×2,
  M4-9 ×2), mock-ветвь `postedit` на `/v1/chat/completions` + `_postedit_response`
  (окружение: 5 профилей, postedit → mock, черновик (M3) → постредактура (M4) на том же
  `job_id`).
