# CONTROL — L3: правка перевода по глоссарию

**Дата:** 2026-09-13 · **Ветка/PR:** `stage/L3` → `main`

Метод: отдельная стадия `GLOSSARY_FIX` после `validating_output` (15 статусов
всего; T-E3-2: 49/176 допустимых переходов 15×15, воркер переходит в стадию
ДО её исполнения — E3.3). Стадия всегда присутствует (L3.10): при
`glossary.fix_enabled=false` — no-op с отчётом (`l3_fix_report.json`),
обнаружение расхождений (L2) при этом не выключается. На входе — свежий замер
ТЕКУЩЕГО `target.epub` (L3.5/идемпотентность): повторный прогон стадии по
исправленному файлу находит 0 расхождений; устаревший отчёт L2 никогда не
доверяется. Правимое множество — три условия одновременно (L3.1): термин в
исходном сегменте; в блоке перевода нет ни одной формы подтверждённой
парадигмы; парадигма `verified` (`paradigm_unverified` — только отчёт, L3.9).
Порог `glossary.fix_max_segment_share` (дефолт 0.5, строго `>`) проверяется
ДО LLM-вызовов: превышение → `AppError` «L3-6» → `FAILED` с отчётом,
книга не переписывается (L3-6). Правка — патч БЛОКА по XPath карты E6
(подстрока запрещена ТЗ); ответ LLM (задача `glossary_fix`,
`prompts/glossary_fix/v1.yaml`) проходит 5-точечную детерминированную
валидацию: 1) в переводе есть форма парадигмы; 2) Δчисла предложений ≤
`fix_sentence_delta`; 3) сигнатура разметки блока (теги+атрибуты) сохранена;
4) язык результата ≠ исходный (детект с уверенностью ≥ `min_confidence`);
5) не пусто и ≠ исходному блоку. Невалидная — отклонена с перечнем пунктов,
без повторной попытки; применённая — ровно с `points == []`. Каждое
применение — запись в `quality.log` (JSON: segment_id, doc, term,
old/new_variant, prompt_file, prompt_version, model, timestamp). До
пересборки — стабильный бэкап `target.epub.l3bak` (записывается до `.partial`);
пересборка — общий `atomic_finalize` (fsync файла → внутренняя валидация →
EPUBCheck → FATAL/ERROR = отказ публикации → `os.replace` → fsync каталога,
Rule 6/8). После применённых правок — пересчёт D61: повторный aligner E6 по
исправленному файлу, `check_consistency`, QC, EPUBCheck, `quality.json`
перезаписывается после каждого замера. `quality.json` → секция `l3`:
`fixable_segment_share`, `attempted`, `applied`, `rejected`,
`editable_share_after`. LLM — mock-сервер (D3, rot3 + инъекции); реальные
LLM-прогоны не проводились (BLOCKER-1). Proгон — `python tests/l3_evidence.py`,
тесты — `pytest tests/test_l3_glossary_fix.py` (14, включая T-L3-11…15).
Verbatim-захваты: `docs/CONTROL/evidence/L3/l3-1…l3-10*.txt`.

## Метрики и механизмы (измерено vs не проверено)

**Измерено** (артефакты в колонке «Артефакт»):
- 100% правимого: 3/3 и 20/20 (включая три разных неверных варианта одного
  имени в 20 вхождениях — T-L3-11: 20 запросов, 20 записей, 0 отклонений,
  `editable_share_after=1.0`) — L3-1;
- 0 правок без записи `quality.log` (3/3, 20/20) — L3-2;
- применённые — только с `points==[]`; отклонённые с перечнем пунктов и
  причиной, без повторных попыток (T-L3-14) — L3-3;
- 0 потери разметки: сигнатура блока сохранена, гиперссылка+сноска на месте
  (T-L3-12) — L3-4;
- повтор: 0 расхождений / 0 правок / файл побайтово тот же (свежий замер на
  входе) — L3-5;
- превышение доли (60% > 50%): остановка с отчётом, 0 правок, 0 LLM-вызовов,
  книга не переписана (T-L3-13) — L3-6;
- пересборка: EPUBCheck 0 ERROR, mimetype STORED первой записью — L3-7;
- kill -9 ×10: 0 повреждённых, l3bak цел, результат после resume = эталонный
  (T-L3-8) — L3-8;
- unverified: 0 автоправок, 100% сообщено отдельным перечнем с собственной
  долей — L3-9;
- 5/5 языков; no-op при выключенной правке, обнаружение при этом работает —
  L3-10;
- T-L3-15: diff бэкапа и результата = ровно список изменений из `quality.log`
  (3 изменённых блока = 3 записи; прочие записи архива побайтово, порядок
  записей сохранён).

**Не проверено / честно:**
- **реальные LLM-прогоны не проводились** (BLOCKER-1): LLM — mock (rot3 +
  инъекции). Механика (отбор, валидация, пересборка, идемпотентность, kill)
  от модели не зависит; поведение реальных моделей (качество «исправления»,
  частота отказов 5-точечной валидации, доля halt-ситуаций) — не проверено;
- **смысловая корректность исправления не проверяется** — по ТЗ L3 проверяет
  форму: термин/парадигма, Δпредложений, разметку, язык; «стало лучше по
  смыслу» — вне детерминированной валидации (LLM не арбитр — Rule 5);
- mock-вклад «тройки» — детерминированный по слову (`sum(ord) % 3`): один
  fill-ответ движка = весь XML главы, поэтому инъекция — по вхождению, не по
  документу (первая `search+replace` дала бы один вариант на всю главу —
  дефект mock, найден и исправлен в T-L3-11);
- п.4 валидации — «язык ≠ исходный»: на mock-переводах (rot3) детект всегда
  уверен в «не-исходном» — реальные модели могут возвращать исходный язык
  (отклонение сработало бы, но частота — не измерена);
- kill-ассерты content-level (байты главы): метаданные zip (date_time записей)
  движком детерминированно НЕ сохраняются (`Zip.replace` — текущее время),
  хэш целого архива между прогонами сравнимым быть не может; целостность
  EPUB подтверждена `read_epub` + `is_zipfile` + l3bak == доправки;
- в mock-мире финальный текст перевода идёт через FILL-путь движка (как в
  L2); правка работает с финальным файлом, путь не важен для критериев.
