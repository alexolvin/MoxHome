## Метрики и механизмы (измерено vs не проверено)

**Измерено** (артефакты в колонке «Артефакт»):
- 5/5 фикстур: язык верен, уверенность 1.0, решение `accepted` (L0-1);
- конфликт dc/детектора → NEEDS_CONFIRMATION 3/3 (100%) + 7/7 веток правил `decide()`
  в тесте, включая границу p=порог и алиасы реестра (L0-2);
- 6/6 (100%) degraded/unsupported пар с точным перечнем недостающего;
  supported ⟺ missing пусто (L0-3);
- «удаление» spaCy-модели: 11/11 пар unsupported, старт приложения 0 падений (L0-4);
- UI-статус == резолвер: расхождение 0 на 11 парах (L0-5);
- supported = 5 (все исходные → ru) (L0-6);
- T-L0-7: конфликтная книга → подтверждение, без авто-выбора, confirm с выбором
  пользователя → план по подтверждённому языку;
- T-L0-8: двуязычная книга → факт (share 0.285714) + 2 пометки de-сегментов (L0.6);
- production-конфиг без правок: 5/5/1 (supported/degraded/unsupported).

**Не проверено / честно:**
- UI (U1) ещё не построен: L0-5 доказан на уровне единой точки (`services.languages`)
  — UI по построению обязан читать только её (Rule 8), «расхождение 0» структурно
  обеспечено, а не измерено на рендере;
- реальный LLM-эндпоинт (BLOCKER-1) не задействован: стадия validating не вызывает
  LLM (E2.5), доказательства воспроизводимы (seed=42);
- многоязычная доля считается как помечено/ВСЕ сегменты: короткие сегменты
  (< `segment_min_chars`) не детектируются (детектор на них ненадёжен) и учитываются
  в знаменателе как «не отличающиеся» — консервативно (не завышает долю, D44);
- «удаление spaCy-модели» (L0-4) — шов `spacy_available=False`, а не физическое
  удаление пакета модели: деструктивное действие на машине не требуется, семантика
  та же (резолвер не видит модель).
