## Дефекты, найденные и исправленные на этапе (Rule 3 — честно)

1. **QC п.6 ложно срабатывал на все переводы (24 находки на complex).** Логика
   `cnt_trans > src_counts[text]` при детерминированном mock (rot3: перевод никогда
   не совпадает с оригиналом) помечала каждый перевод «дублированием». Исправлено:
   дублирование — только `out_counts[T] > src_counts[T] + trans_counts[T]`
   (ожидание = оригиналы + спаренные переводы), п.5 — симметрично (D25).
2. **QC п.7: 65 ложных находок на complex (49 namespace + 16 tail).**
   (a) Сравнение `nsmap`: движок убирает неиспользуемую корневую декларацию
   `xmlns:epub` (E1), а `nsmap` lxml несёт наследуемые префиксы — «находка»
   размывалась по всем потомкам; (b) сравнение tail: движок вставляет перевод
   вплотную к оригиналу (`</h1><h1__translated>`) — whitespace-хвост оригинала
   вокруг точки вставки меняется. Исправлено: namespace-декларации не сравниваются
   (сериализационная деталь; реальное повреждение видно в тегах/атрибутах Clark +
   EPUBCheck), whitespace-only tail не сравнивается; известная ресериализация —
   только корневой `lang` (D24).
3. **Адаптер поглощал кооперативную отмену: CANCELLED становился FAILED.**
   `WorkerCancelled` поднимается нашим `control_check` внутри `on_progress` движка,
   т.е. внутри `translate()`; общий `except Exception: raise LLMUnavailableError`
   адаптера превращал отмену в «сбой тракт T» (измерено: `test_e3_6` → FAILED,
   пустая причина = `WorkerCancelled()`). Исправлено: адаптер не переинтерпретирует
   исключения движка; семантику «тракт T недоступен» назначает конвейер, а
   кооперативные исключения (`WorkerCancelled/WorkerPaused/LeaseLost`) пропускает
   как есть (D23).
4. **(Фикстуры) отсутствие `dcterms:modified` в OPF фикстур → EPUBCheck RSC-005
   на исходниках.** Исправлено в `tests/fixtures/epub/build.py`, фикстуры
   перегенерированы (до контрольных прогонов E5: исходники 0/0, см. E5-3).

## Замечания

- **PASS на mock (D3).** Все контрольные значения измерены на детерминированном
  mock-эндпоинте (rot3-преобразование). Реальные прогоны с живым LLM не выполнялись
  (BLOCKER-1) и PASS'ами не заявляются.

  (секция `<rules>`) — измерено в E5 (mock requests_log); в fill-шаблон
  `user_prompt` не передаётся (epub-translator 0.1.10).
- **Fill-события:** движок emits на группу: по одному событию на каждый повтор
  (`over_maximum_retries=False`, `retried_count=1…5`) + финальное
  (`over_maximum_retries=True`). Механизм фиксирует все события (строже ТЗ, который
  требует критические); критические — отдельно подсчитаны (E5-6: 2 из 12).
- **Известная ресериализация движка (п.7):** корневой `lang` удалён (`xml:lang`
  сохранён) — 1 поимённая находка на документ, предупреждением не является
  (поведение движка, не повреждение книги); неиспользуемые namespace-декларации
  сравниванию не подлежат (D24). Всё остальное изменение структуры — предупреждение.
- **Кэш движка изолирован по модели (D15):** `engine_cache/<модель>/` (translation
  и fill — разные каталоги при разных моделях).
- **Анализ (анализирующие стадии) не затронуты:** `analyzing`/`generating` остаются
  плейсхолдерами (L1/L2/S-этапы); `config_hash` — профили translation+fill (D21).
- **Зависимости:** новых runtime-зависимостей нет (epub-translator, lxml, java/EPUBCheck
  — уже в E1/E2/D4).
