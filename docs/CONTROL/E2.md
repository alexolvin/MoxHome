## Замечания

- **Движок делит книгу на группы** (измерено в E1 и подтверждено здесь): `complex.epub`
  даёт 2 translate-запроса, поэтому «фактический расход» в E2-5 = сумма user-токенов
  всех translate-запросов, а не одного.
- **marked_text без namespace-шума:** lxml при ресериилизации вставляет
  `xmlns`/`xmlns:epub` в каждый inline-элемент; сегментатор копирует поддерево
  без namespace-деклараций (`_plain_copy`), иначе верbatim-сравнение разметки было бы
  невозможно.
- **Путь в segment_id — путь в архиве** (`OEBPS/z_alpha.xhtml`), а не путь на диске:
  id стабильны независимо от run-каталога (проверено в E2-1).
- **Порядок валидации** (fail-closed, до LLM): ZIP → mimetype первой записью →
  DRM (отказ до распаковки) → container.xml → распаковка (защита от zip-slip) →
  OPF → manifest → spine → разбор каждого spine-XHTML; нечитаемый документ —
  `InputValidationError` (E2.5, T-E2-7).
- `tiktoken` добавлен как явная зависимость (`uv add tiktoken`, ≥ 0.14.0).
- Для mypy добавлены локальные стробы `stubs/lxml/etree.pyi` (поверхность, которую
  использует проект; lxml не публикует py.typed).
