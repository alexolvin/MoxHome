## Дефекты, найденные и исправленные на этапе (Rule 3 — честно)

1. **Инвариант `tokens_total` в одном `UPDATE` не работал.** SQLite вычисляет правые
   части `SET` от *исходных* значений строки (измерено: `SET f=f+50, total=t+f` не
   видит прирост) → пересчёт `tokens_total` в том же выражении, что и инкремент
   профиля, недоучитывал дельту последнего профиля (замер: total=5911 при сумме
   9974). Исправлено: отдельный `UPDATE` на пересчёт после инкремента (D22).
2. **Mock-сервер отвечал только SSE-стримом.** Не-streaming запрос `stream:false`
   (режим OpenAI, используемый клиентом анализа) не поддерживался →
   `response.json()` падал. Исправлено: mock возвращает единый JSON-ответ с `usage`
   при `stream:false`, SSE — при `stream:true` (движок не изменён).
3. **Потоки-хендлеры mock-сервера не были демонами.** Сценарий `timeout` (сон 30 с)
   держал бы выход тестового процесса до 30 с. Исправлено: `daemon_threads=True`.

## Замечания

- **Скоуп E4-1.** Критерий «URL, имена моделей, порты, ключи» понимается как
  LLM-эндпоинты: адреса, модели и ключи LLM. Стандартные XML-неймспейсы протоколов
  EPUB (idpf.org, w3.org, purl.org) — константы формата в парсере, не сетевые
  настройки; их исключение зафиксировано в evidence и D21. Числовые «порты» без
  адреса не имеют смысла — охвачены grep'ом URL.
- **Движок (тракт T) не использует `stream:false`:** `epub_translator` шлёт
  `stream=true` (измерено в E1), поэтому mock отдаёт SSE для translate/fill и JSON
  для analysis — как реальный OpenAI-совместимый сервер.
- **Токены неудачных попыток учитываются** (E4.7, тракт A): usage ответа засчитывается
  до валидации; при исчерпании повторов задание несёт токены всех попыток
  (замер E4-4: 1002).
- **`analyzing` — заглушка в pipeline (E4):** задачи реестра (`analysis_vocabulary`,
  `analysis_grammar`, `analysis_glossary`) и промпты v1 заложены, исполнение в
  конвейере — этапы L1/L2; `config_hash` пока по профилям translation/fill (D21).
- **Промпты:** 4 файла (generic v1 ×3 + pair en/de v1 для `analysis_glossary`);
  версии — наибольший N уровня; при конфликте уровней побеждает пара (замер
  `test_resolver_level_and_version_selection`: v3 pair > v1 source > v2 generic).
- **Зависимости:** добавлены `jsonschema` (runtime) и `types-jsonschema` (dev) —
  `uv.lock` обновлён.
