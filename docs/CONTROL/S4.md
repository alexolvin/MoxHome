# CONTROL — S4: summary, вопросы, упражнения

**Дата:** 2026-09-13 · **Ветка/PR:** `stage/S4` → `main`

Метод: три подстадии стадии `LEARNING` (ТЗ_03, после S3), материалы
строятся по тексту языка-ИСТОЧНИКА (пары E6, как S1–S3):
`s4_summary` (`Intensive`), `s4_questions` (`Learning`/`Intensive`),
`s4_exercises` (`Intensive`) — гейт уровней `SUBSTAGE_LEVELS`
(данные `app/learning/__init__.py`); вне уровня подстадия не исполняется
и артефактов не выпускает. Идемпотентность — собственные ключи
`stage_results: "s4_summary" | "s4_questions" | "s4_exercises"` (та же
формула `sha256(input_hash | glossary_hash | level | cefr)`, что у
S1/S2/S3; упражнения — плюс hashes `vocabulary_cards.json`/
`grammar_notes.json`, т.к. строятся из выпусков S1/S3).

Вводная для всех трёх подстадий — `_s4_chapter_data`: пары
сегмент «источник → перевод» по выровненным сегментам главы; главы
БЕЗ текстовых сегментов (пустые, только изображения) исключаются до
обращения к LLM — S4.1/T-S4-8: «суммаризация по названию главы
запрещена; при пустой или нечитаемой главе summary не создаётся, а
фиксируется пропуск» (запись `skipped` с причиной + warning в
`quality.json`).

LLM — три новые задачи (`app/llm/tasks.py`, промпты
`prompts/chapter_{summary,questions,exercises}/v1.yaml`), по главам
(никогда не вся книга, ТЗ общее требование 5): `chapter_summary` —
ОДНО объект-изложение (краткое/расширенное, ключевые события,
сущности, темы, понятия); `chapter_questions` — пакет из 15 вопросов
(5 easy + 5–10 standard + 1–5 advanced; типы gap/mc/tf/free, schema-
валидация); `chapter_exercises` — пакет упражнений 7 типов (mc, tf,
gap, translation, vocab, grammar, free — состав типов = конфиг
`limits.exercises_types`, поле с валидатором).

Детерминированная валидация ПЕРЕД выпуском (`validate_summary` /
`validate_question` / `validate_exercise`, `app/learning/study.py`),
отклонённые не исчезают — `rejected` с причинами в отчётах + warning:
1) gap: удалённое слово ФАКТИЧЕСКИ в исходном предложении
(`split_words`, casefold; blank — конвенция `____` на первом
вхождении, `blank_first_occurrence`; S4-2); 2) mc: ≥2 вариантов,
без дублей (casefold), ровно ОДИН правильный, ответ = текст
правильного (S4-3); 3) tf/free/mc/gap: упоминаемые сущности
(`entities`) присутствуют в тексте главы (`contains_form`, Rule 8;
S4-4); 4) vocab: `source_ref.kind=card` → id среди ВЫПУЩЕННЫХ S1-
карточек главы; grammar: id среди выпущенных S3-заметок; translation:
промпт — предложение главы (S4-6: «не порождают новый материал»);
5) summary: непустое brief/extended, списки на месте. «Правильный
не выделяется длиной» (ТЗ S4.5) — системная проверка РАСПРЕДЕЛЕНИЯ
по 100 mc (T-S4-9), не поединковая: порознь «самый длинный»
допустим (в реальных текстах длинные варианты часто и есть
правильные), гейтится систематичность. Ответы — ОТСЕЧЕНИЕ (S4-5):
записи вопросов/упражнений (тело учебной главы) не содержат полей
`answer`/`correct`; ВСЕ ответы — в отдельной сущности
`answers.json` (`{chapters: {ch: {questions: {qid: …},
exercises: {eid: …}}}}`), связь — по id. mc-ответ — индекс
правильного варианта (строкой), gap — слово, tf — true/false, free —
эталонный текст. Детерминированные id — `uuid5(NAMESPACE_URL,
"s4:{chapter}:{type}:{текст.casefold()}").hex` (стабильно между
прогонами, дедупликация — по `type|текст.casefold()`). Записи
несут трассируемость ТЗ_03 общих требований 1–2 (`chapter_id`,
`segment_id`, `source_language`/`target_language`,
`user_level`/`user_cefr`, `prompt_file`/`prompt_version`, `model`,
`profile`, `timestamp`, glossary_hash через input_hash ключа).
`quality.json` → секция `s4`: `summary` / `questions` / `exercises`
(`enabled`, итоги, версии, `report`). LLM — mock-сервер (D3,
детерминированная генерация по фактическим предложениям главы;
сценарии `s4_gap_missing_word`, `s4_mc_two_correct`,
`s4_mc_dup_option`, `s4_entity_ghost`, `s4_vocab_ghost`); реальные
LLM-прогоны не проводились (BLOCKER-1). Прогон —
`python tests/s4_evidence.py`, тесты — `pytest tests/test_s4_study.py`
(21 запуск: T-S4-1…T-S4-9, из них T-S4-7 ×5 языков). Verbatim-захваты:
`docs/CONTROL/evidence/S4/s4-1…s4-9.txt`.

## Метрики и механизмы (измерено vs не проверено)

**Измерено** (артефакты в колонке «Артефакт»):
- главы без текстовых сегментов: summary 0, пропуски зафиксированы с
  причиной (2/2, включая главу-изображение) — S4-1/T-S4-8;
- 0 gap с чужим словом (отклонение с причиной, verbatim) — S4-2;
- 0 mc с числом правильных ≠ 1 / с дублем вариантов (2 сценария,
  verbatim) — S4-3;
- 0 выпущенных с отсутствующей в главе сущностью (verbatim) — S4-4;
- 0 полей answer/correct в теле вопросов/упражнений; answers.json
  полная 1:1 (300/300, 169/169) — S4-5;
- 100% vocab-упражнений из выпущенных S1-карточек (29/29,
  vocab_from_cards=1.0); призрачный источник отклонён — S4-6;
- 5/5 исходных языков со всеми тремя подстадиями + гейт уровней — S4-7;
- mc-распределение: 100 вопросов, 4 позиции, топ 26%, самый длинный
  38% — T-S4-9.
- Тесты: 244/244 (223 + 21 запуск T-S4-1…T-S4-9), ruff 0, mypy 0
  (64 файла).

**Не проверено / ограничения (честно):**
- LLM-суммаризация/вопросы/упражнения — mock (D3): реальные
  LLM-прогоны не проводились (BLOCKER-1). Реальные механизмы: вводная
  по выровненным сегментам, отсев нетекстовых глав, 4-пунктовая
  детерминированная валидация (gap/mc/sущности/ссылки на выпуски
  S1/S3), отсечение ответов, дедупликация, uuid5-id, метрики и
  отчётность; mock — детерминированная генерация по фактическим
  предложениям главы + 5 сценариев инъекций.
- «Правильный не выделяется длиной» (ТЗ S4.5) гейтится как
  РАСПРЕДЕЛЕНИЕ по книге (T-S4-9: доли позиции и длин), не как
  порознь «не самый длинный» — в фактических текстах поединковый
  запрет ложился бы на сам контент, а не на систематический сбой;
  порогов ТЗ нет, избрано: топ-позиция < 60% и «самый длинный»
  < 60% (фиксировано в T-S4-9).
- Пересечение с S3: grammar-упражнения из выпущенных заметок
  валидируются как vocab (S4-6); на S4-фикстурах S3-заметок нет
  (кандидатов 0) — ветка `grammar_from_notes` покрывается unit-тестом
  и кодом, сквозного прогона с заметками нет (честный предел
  фикстур).
- Свободные ответы (free): детерминированной семантической проверки
  «вывод следует из текста» нет — только наличие упоминаемых
  сущностей в главе (как и для всех типов, TЗ S4.5 п.4); качество
  эталонного ответа — за LLM (mock).
- Сводки (summary) не проверяются на верность по тексту (фактчекинг) —
  ТЗ требует только построения по фактическому тексту (исходник
  segments) и структуры; фактчекинг — за LLM (BLOCKER-1).
