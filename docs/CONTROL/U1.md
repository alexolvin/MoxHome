# CONTROL — U1: Web UI и API

**Дата:** 2026-09-14 · **Ветка/PR:** `stage/U1` → `main`

Метод: слой представления по ТЗ_04 §U1 — FastAPI + серверный HTML (Jinja2)
+ минимальный vanilla JS (фреймворков и сборочных инструментов нет, D69);
разделы Books / Jobs / Languages / Models / Prompts / Settings. Сервер —
`python -m app.web` / `app.__main__` (uvicorn, bind/port из конфига).
Воркер — отдельный процесс `python -m app.workers.run --loop`; запуск
воркера из UI не реализован — в футере страницы явно
«запуск из UI: Not implemented» (Rule 7: незавершённое помечено).

Доступ (U1-7/U1-8): HTTP Basic на всех маршрутах (страницы + /api +
/static) через middleware; пароль = `SERVER_AUTH_SECRET`, любое имя,
сравнение `hmac.compare_digest`; пустой секрет → доступ открыт, в футере
«auth: off». Секреты в HTML и access log не попадают: конфигурация отдаётся
в `/api/config` в виде «задан»/«не задан», логи задания отдаются как
plain-строки без полей секретов (конфигурация logging уже маскирует
secrets, `setup_logging(secrets=…)`).

Здоровье (U1-3): `GET /api/health` — покомпонентный, БЕЗ общего флага:
`app`, `database` (`repo.ping`), `storage` (запись/чтение/удаление
контрольного файла в `storage.root`), `llm` по каждому профилю
(`GET {base_url}/models`, Bearer при ключе, timeout 5 c → `ok` /
`error (ConnectError)` / `error (HTTP …)`), `nlp` по каждому языку
(spacy-модель загружаема; целевой `ru` → `n/a (целевой язык)`),
`epubcheck` (jar + java). LLM выключен (мёртвый порт) → `llm/*` = error с
причиной, общий «healthy» отсутствует.

Честный прогресс (U1-1/U1-2): единственный источник —
`translation_phases(validation)` (модуль `app/workers/pipeline.py`, тот же
механизм, что использует воркер в callback'е — Rule 8); фазы
TOC (0.05) / metadata (0.05) / главы (равная доля остатка). API и HTML
показывают «глава N / M, сегментов X / Y» (или «фаза: TOC (сегментов
X / Y)»); процент — ТОЛЬКО для измеренного охвата выравнивания E6
(`jobs.alignment_coverage`, метка «E6»); ETA — `elapsed·(1−p)/p` с меткой
«оценка». Фиктивных процентов нет (U1-2: каждое «%» на страницах и в JSON
равно измеренному охвату).

Endpoint ↔ потребитель (U1-6): каждый `/api`-маршрут (каждый метод)
имеет потребителя в UI — серверный `data-u1-fetch` в шаблонах или
`fetchJSON`/шаблонные литералы в `app.js`/`job.html`; контроль — таблица
маршрутов приложения против литералов в файлах (0 без потребителя).

Данные (U1-9): список правок L3 в UI (`/api/jobs/{id}/quality` →
`l3.fixes`) — из `l3_fix_report.json` (тот же артефакт, что пишет стадия
L3); каждая фактическая правка имеет запись `kind=glossary_fix` в
`quality.log` — сопоставление по (segment_id, doc, term), 0 расхождений в
обе стороны. В конфигурации U1-тестов `glossary.fix_enabled: true`
(боевой `config/config.yaml` — по-прежнему без правки, D63: стадия
всегда существует, no-op честно помечен).

База данных: `Database` — подключение на нить (`threading.local`): sync-
эндпоинты FastAPI исполняются в пуле anyio, соединение, привязанное к
ниту создания, вызывало `ProgrammingError`; WAL + `busy_timeout`
сериализуют доступ между соединениями (регрессий нет: полный
тестовый прогон зелёный).

Прогон: `python tests/u1_evidence.py`, тесты — `pytest
tests/test_u1_web.py` (10 запусков T-U1-1…T-U1-10; T-U1-9 — полный цикл
20-главной книги с Learning/B1, T-U1-10 — stop mock-сервера в
TRANSLATING). Verbatim-захваты: `docs/CONTROL/evidence/U1/`.

## Метрики и механизмы (измерено vs не проверено)

**Измерено** (артефакты в колонке «Артефакт»):
- 40/40 срезов живого прогона: progress(API) == progress(БД),
  display == чистой функции, 0 «%» — U1-1;
- 0 фиктивных процентов: все «%» = измеренный E6 (100.0 при
  coverage 1.0) — U1-2;
- health покомпонентный: llm/* = error с причиной, общего «healthy»
  нет, nlp/ru = «n/a (целевой язык)» — U1-3;
- 11/11 пар API == свежему резолверу L0 (статус/missing/creatable)
  — U1-4;
- 6/6 derived-языков — «Estimated CEFR level» во всех местах
  отображения — U1-5;
- 16 endpoint'ов (19 метод-строк), 0 без UI-потребителя — U1-6;
- 17/17 маршрутов — 401 без секрета / работают с ним, неверный
  секрет — 401 — U1-7;
- 0 вхождений секретов (2 секрета × 13 путей) в ответах и в access
  log реального uvicorn — U1-8;
- L3: 3 фактические правки, UI == quality.log по 3/3 (обе стороны 0
  расхождений) — U1-9;
- полный цикл API (20 глав, Learning/B1) — результат побайтово;
  LLM-off в TRANSLATING → FAILED + причина в UI (T-U1-9/T-U1-10).
- Тесты: 266/266 (256 + 10 запусков T-U1-1…T-U1-10), ruff 0
  (`app/` + `tests/`), mypy strict 0 (73 файла).

**Не проверено / ограничения (честно):**
- Привязка к Tailscale (V1.11, доступ с другой машины) — не
  проверялась: в окружении нет второй машины; bind-адрес читается из
  конфига и передаётся uvicorn, фактической проверки через
  Tailscale-интерфейс нет (V1).
- Реальные LLM — mock-сервер (D3): health-проба `GET /models`
  и все LLM-сценарии — на mock'е; поведение с реальным провайдером
  не проверялось (BLOCKER-1 на все стадии).
- Anki-импорт — не проверялся (S5-7, BLOCKER): в U1 только выдача
  `cards.anki.tsv` по существующему экспорту S5.
- Запуск/управление воркером из UI — Not implemented (по ТЗ: воркер —
  отдельный процесс); пауза/возобновление/отмена заданий из UI
  реализованы (кооперативные флаги E3.8), фактического stop воркера
  из UI нет.
- Kill -9 API-процесса в середине ответа — не проверялся (не в
  критериях U1; устойчивость пайплайна к kill покрыта S5-9/L3-8).
- Боевой `config/config.yaml` не изменён: `glossary.fix_enabled`
  там отсутствует (D63, правка L3 выключена по умолчанию); U1-9
  проверяет путь с правкой в тестовой конфигурации (`fix_enabled:
  true`), no-op-путь (правка выключена) честно помечен
  `l3_fix_report.json` (`reason`) и виден в UI.
