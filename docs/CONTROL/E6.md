## Метрики и механизмы (измерено vs не проверено)

**Измерено** (артефакты в колонке «Артефакт»):
- покрытие 1.0 на всех 5 фикстурах (26/26 + 3/3×4), `identity_mismatches=0` (E6-1, E6-2);
- невыровненные поимённо с причиной 1/1, фиксированный набор причин TZ (E6-3);
- перестановка: 5/5 вариантов обнаружены, «уверенных неверных пар» нет (E6-4);
  честное ограничение — межамена переводов ДВУХ блоков без id одного тега не
  обнаруживается (E1: «без id — только позиция»);
- повторный прогон — побитово идентичный отчёт (sha256, E6-5);
- один источник охвата: job == quality == report, diff 0.0 ×5; ниже порога —
  предупреждение + `COMPLETED_WITH_WARNINGS` (E6-6);
- 38/38 (100%) пар с разрешимым XPath перевода; вложенные структуры (таблица,
  сноска, blockquote) не сломаны — T-E6-7 (E6-7);
- REPLACE: 26/26 inplace, источник — исходный файл, оригинал в выходе отсутствует
  (T-E6-8);
- измеренный факт сдвига позиционных XPath оригиналов вставленными sibling'ами —
  справочник = (doc, исходный XPath, текст) + измеренный XPath перевода;
- белий список «идентичны оригиналу» — настраиваемый regex
  (`alignment.identical_whitelist_pattern`), по умолчанию — цифры/пунктуация;
  неверный regex → `ConfigurationError` при загрузке конфига (fail closed, тест).

**Не проверено runtime-мерой (честно):**
- реальный LLM-эндпоинт: весь этап на mock (D3, rot3) — **PASS реальных прогонов не
  заявляется (BLOCKER-1)**;
- UI-показ охвата — этап U1 (сервер ещё не запускается); проверены данные:
  единая колонка `jobs.alignment_coverage`, расхождение 0 с отчётом (E6-6);
- фактическая правка L3 по карте: карта проверена (разрешение + тег + текст), сам
  патч — этап L3; после L3 выравнивание пересчитывается по исправленному файлу
  заново — механизм: `build_alignment_report` без кэша строит отчёт только из
  текущих файлов, переиспользовать старую карту нечем (TZ E6.7).

**Гарантировано конфигурацией/конструктом, runtime-мерой не проверялось отдельно:**
- порог `min_coverage=0.995` и белый список — значения из YAML (Rule 1, D35);
- S1–S4 работают по выровненному подмножеству: вход учебных этапов —
  `alignment_report.json → docs[].aligned`, иного пути механизм не предоставляет;
  охват передается явно (колонка + сводка в `quality.json → alignment`).

## Дефекты, найденные и исправленные на этапе (Rule 3 — честно)

1. **Контейнерные пары (blockquote) не выстраивались: полный текст контейнера в
   выходе = оригинал + вставленный перевод.** При вставке внутрь (E1 §3 п.5)
   `full_text(blockquote)` в выходном файле включает вставленный `<p>` —
   пересчёт идентичности «по всему тексту» давал `xpath_mismatch` на всех
   контейнерных парах. Исправлено: `original_text(out_el, src_el)` — текст выходного
   элемента БЕЗ вставленных поддеревьев (блок-дети выхода сопоставляются оригиналу
   по `(тег, оригинальный текст)`, несопоставленные — вставки; inline-дети — никогда
   не вставки) (D33).
2. **Тег и маркер брались с контейнера, а не с корня сегмента движка.** Для
   blockquote корень сегмента движка = внутренний `<p>` (E1 §3 п.5, `block_parent`):
   тег перевода — `p`, маркер — `inner-id__translated`. Проверка «ожидался
   blockquote, найден p» ломала все контейнерные пары. Исправлено: `text_root` —
   единственный блок-потомок (кроме самого элемента), несущий весь текст сегмента;
   тег/маркер/ожидаемая позиция перевода берутся с `text_root`. Первая версия функции
   учитывала сам элемент в `iter()` (desc = 2) и возвращала контейнер — ловлено
   пробом до релиза (D34).
3. **Первая реализация `resolve_positional_xpath` не знала фактический формат
   позиционного XPath.** Формат — сегменты склеены БЕЗ разделителей, корневой сегмент
   без индекса: `/htmlbody[1]p[3]` (не `/html/body/p[3]`); первая версия
   (`split("/")`) разрешала 0/38 XPath. Переписана с дерево-управляемой
   токенизацией (корневой сегмент = корень, без индекса; далее — префикс имени
   без индекса + опциональный `[N]` на шаг). Ловлено пробом E6-7 до релиза.
4. **`extra_block`: смещённые оригиналы сообщались как вставки.** Сценарий e
   (нетронутой паре — конец документа): оригиналы, не сопоставленные монотонно
   (li1, li2, blockquote, внутренний p), попадали в множество «вставок» — extra=7
   вместо 3, нарушение порядка при этом частично замалчивалось. Исправлено: вставка —
   только элемент с маркером перевода в id или (тег, текст) не принадлежащий НИ ОДНОМУ
   оригиналу (`_is_original`, D37); само нарушение порядка обнаруживается
   монотонностью как `xpath_mismatch` (TZ E6.4: обнаружить, а не переименовать).
5. **(Латентный дефект E5) Предупреждения в `quality.json` не совпадали со статусом
   задания.** В E5 `quality = {**report, "checks": …}` — предупреждение
   конвейерного уровня («в выходной книге нет сегментов») попадало в статус
   (`COMPLETED_WITH_WARNINGS`), но не в отчёт. Исправлено: `quality["warnings"]` =
   полный набор (QC + конвейер + E6); проверено: `quality["warnings"]` ==
   возвращённый воркеру набор (True, E6-6).

## Замечания

- **PASS на mock (D3).** Все контрольные значения измерены на детерминированном
  mock-эндпоинте (rot3-преобразование). Реальные прогоны с живым LLM не выполнялись
  (BLOCKER-1) и PASS'ами реальных прогонов не заявляются.
- **«Показан в UI» (E6-6) — UI-часть отложена до U1** (сервер ещё не запускается).
  Данные проверены: единое значение `jobs.alignment_coverage` (S-стадии и UI
  читают его), расхождение 0 с `quality.json` и отчётом; ниже порога →
  `COMPLETED_WITH_WARNINGS` — готовая логика воркера (E5, T-E5-11).
- **«100%» перестановок (E6-4)** = 5/5 вариантов, ломающих пары (межамена с id,
  сдвиг, удаление ×2, нарушение порядка). Межамена переводов ДВУХ блоков без id
  одного тега — не обнаруживается механизмом (E1: «без id — только позиция»);
  ограничение заявлено честно в evidence.
- **Измеренный факт сдвига позиционных XPath:** индексы оригинальных блоков в выходе
  сдвинуты вставленными sibling'ами (сноска `p[4]` → перевод `p[8]`); ищем оригинал в
  выходе НЕ «по XPath сегментации в выходе» (невозможно), а (doc, исходный XPath) +
  текст из выходного элемента; карта хранит ИЗМЕРЕННЫЙ XPath перевода (L3).
- **После L3:** выравнивание пересчитывается по исправленному файлу заново;
  переиспользование карты, построенной до правки, запрещено (TZ E6.7) — механизм:
  `build_alignment_report` без кэша читает только текущие исходный и выходной файлы.
- **REPLACE (T-E6-8):** исходный текст для учебных материалов всегда — из исходного
  файла (отчёт строится от исходной книги); поле отчёта `source_text_source`
  гласит об этом явно — S-стадии читают оригинал из `source_text`, не из выхода.
- **Новый конфиг** (Rule 1 — значения в YAML): `alignment.min_coverage`
  (дефолт 0.995) и `alignment.identical_whitelist_pattern` (regex, fullmatch по
  нормализованному тексту перевода; дефолт — цифры/пунктуация
  `^[\d\s.,;:()\-\u2013\u2014/%$€]+$`; неверный regex → `ConfigurationError`).
- **Зависимости:** новых runtime-зависимостей нет (lxml, epub-translator — E1/E2).
