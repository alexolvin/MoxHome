## 2. Выбор: GitHub (`github-com--blog`, система Primer)

Обоснование по пяти обязательным критериям §3.2:

1. **Контраст в обеих темах.** Единственный кандидат с тёмной темой
   first-class: сам захват тёмный, в токенах захвачен полный dark-набор
   (canvas #010409/#0d1117, fg #e6edf3, muted #8b949e, success #3fb950,
   danger #f85149…). По расчёту (не на глаз, §6.1) весь dark-набор
   проходит пороги §6.1 в обеих темах — таблица в §4. Perplexity: тёмная
   тема — инверсия пары inverse-токенов, не самостоятельный набор.
   Next.js: тёмная тема сайта проще и в захвате не представлена.
2. **67-символьные хеши.** Продукт GitHub — система хешей (commit SHA,
   file id), моно-панелей логов (Actions) и status-бейджей: тот же визуальный
   класс, что у страницы задания. В токенах захвата — code-кегль .8125rem и
   mono-весы. У Perplexity mono — служебные токены весов; у Next.js mono
   есть, но плотность таблицы не его жанр.
3. **Плотные таблицы, утилитарная типографика.** Тело 14 px / 1.5, сетка
   4 px, радиус 6 px, border-collapse-таблицы с тонкими линейками — канон
   плотного дашборда (Issues, Actions, PR list). Next.js — документация
   с секциями по 80–96 px (антиплотность). Perplexity — поисковая витрина,
   средняя плотность.
4. **Ноль сетевых запросов.** Выполняется системным стеком (решение §3 ниже);
   собственный фонт-стек GitHub — Mona Sans + системный фолбэк, т. е. система
   спроектирована работать без загрузки шрифта.
5. **Тёмная тема изначально.** Primer — dual-theme с первого запуска
   (canvas-default/canvas-subtle, fg-default/fg-muted в обеих темах,
   status-цвета в обеих темах). У обоих отвергнутых кандидатов тёмная тема
   вторична.

**Отклонены:**
- **Perplexity** — критерии 3 (плотность: витрина, не таблицы) и частично 5
  (тёмная тема = инверсия); палитра захвата аномальна для системы
  (жёлто-зелёный #c8c836 — от research-страницы, не от каркаса);
  pplxSans — проприетарный, самохостинг невозможен.
- **Next.js** — критерий 3 (документация с крупными секциями 80–96 px,
  display-кегль 72 px — маркетинг); без хроматического акцента (монохром) —
  статусные цвета пришлось бы выдумывать, а не брать из системы.

## 3. Шрифты (решение)

Внешние шрифты запрещены (§3.3). Выбор — **системный стек**, зафиксирован
явно в токенах:

```
--u3-font-sans: system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif;
--u3-font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace;
```

- Класс гротеска (консенсус жанра: displayClass grotesk-sans 88 % по 24
  сайтам, evidence recommend) выдерживается системными гротесками:
  Roboto (Android-целевое устройство), Segoe UI (Windows), SF (macOS/iOS).
- Критерий 4 идеален: 0 запросов, 0 байт в бюджете 120 КБ (бюджет
  самохостинга не потрачен — потолок, а не требование).
- Самохостинг Mona Sans (OFL, 2 начертания + system-mono, ≤ 120 КБ)
  зафиксирован как допустимое развитие, если появится потребность в
  межплатформенной идентичности начертания; вне объёма D1.

## 5. Макроструктура страниц

Маркетинговые формы отклонены (§3.1 п. 4). Страницы приложения:

- списки (`/jobs`, `/books`, …) — **Index-First** (захват-пример:
  `perplexity-ai` — точность индекса, 16 px тело, 8-пиксельный ритм);
- страница задания — **Long Document** (стек панелей: факты → лог → QC;
  захват-примеры: `nextjs-org` — нейтральная документальная сетка).

Из выбранного источника (GitHub) переносится только набор значений —
токены; его маркетинговая макроструктура захвата (Feature Stack) приложению
не применяется.

## 6. Ограничения этапа

- Тёмная тема не активирована (D4, §6.2: `@media (prefers-color-scheme: dark)`
  + переопределение токенов, никаких внеблоковых правил под тему).
- Миграция CSS: все литералы цвета/кегля/отступа/радиуса вынесены в `:root`
  (правило §8.1.1). Толщины линий (1px/2px) — не входят в категории токенов
  ТЗ (цвет/кегль/отступ/радиус) и остаются литералами: 2 px — минимум
  контура фокуса по §3.4.
- `--u3-head-bg`, `--u3-pre-bg`, `--u3-cancelled`, `--u3-radius` — удалены
  (объединение в `--u3-surface` / `--u3-muted` / `--u3-radius-md`).
- Регресс после миграции — матрица §4.1 + мобильные метрики (T1/T2/T3),
  т. к. округления сетки меняют паддинги на ≤ 2.4 px.
